# AURA Catalogue — proposed data model

**Status:** design proposal. No PostgreSQL schema or management API is implemented by this document.

## Entities

### Object
- `id`: UUID primary key generated by AURA.
- `bucket`, `object_key`: unique storage locator, private to the service.
- `display_name`: user-facing file name.
- `content_type`: validated MIME type.
- `size_bytes`: non-negative integer.
- `checksum_sha256`: optional until verified; record the algorithm explicitly.
- `folder_id`: nullable foreign key to logical folder.
- `owner_id` / `tenant_id`: ownership boundary.
- `visibility`: private by default.
- `status`: pending, available, quarantined, deleting, deleted, failed.
- `created_at`, `updated_at`, `deleted_at`.

### Folder
- `id`, `tenant_id`, `owner_id`, `parent_id`, `name`, timestamps.
- Enforce name/parent uniqueness according to the product's case-sensitivity rules.
- Prevent cycles on moves.
- Treat folders as logical catalogue records; do not map user-supplied names directly to host filesystem paths.

### ImportJob
- `id`, `tenant_id`, `created_by`, `status`, `total_items`, `processed_items`, `failed_items`, timestamps, sanitized summary.
- Jobs must be retryable/idempotent and should support cancellation where safe.

### AuditEvent
- Actor/service identity, action, target ID, outcome, request ID, timestamp, and safe metadata.
- Never record secrets, signed URLs, authorization headers, or full private content.

## Consistency and reconciliation

S3 upload and PostgreSQL metadata writes are not one atomic transaction. Use a lifecycle:
1. Create a pending upload intent in PostgreSQL.
2. Issue a short-lived upload URL scoped to a generated object key.
3. Verify upload completion and object metadata/checksum.
4. Mark the catalogue object available.
5. Reconcile expired pending uploads and orphaned objects after a safe grace period.

Deletion should first mark an object as deleting/deleted and retain a recoverable window. A separate purge job can permanently delete bytes after policy checks. Log all destructive operations.

## Indexing and scale

Index tenant/owner, folder, status, created_at, and normalized display name. Use cursor pagination for large catalogues. Add full-text search only after measuring actual needs. Store file bytes in SeaweedFS, not PostgreSQL.
